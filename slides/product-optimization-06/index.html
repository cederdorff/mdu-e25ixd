Er Lighthouse det rigtige værktøj?

Ja — til baseline og hypoteser.
Nej — som eneste bevis.

→
NetworkHvad bliver faktisk hentet?størrelse, timing, type, status og gentagelser

BrugerflowHar det betydning?observer appen under realistiske forhold

Lighthouse er en kontrolleret lab-test. Den viser ikke nødvendigvis det, alle virkelige brugere oplever.

Det vigtigste filterHvis vi ikke kan forklare betydningen for brugeren, har vi endnu ikke et prioriteret problem.

Svar eksplicit på spørgsmålet: Lighthouse er egnet til før/efter, hvis betingelserne holdes ens. Network er det vigtigste supplement på deres niveau. Gør forskellen eksplicit: Lighthouse er en kontrolleret lab-test, mens virkelige brugere har forskellige devices, netværk og interaktioner. Stop derefter ved brugerflowet: Hvem rammes? Hvad prøver personen at gøre? Hvad venter, hopper eller reagerer ikke? Og sker det ofte nok til at være vigtigt? Performance-panelet og React Profiler er trin to, når et konkret load eller klik stadig kræver en dybere forklaring — ikke standard for alle. Billeder · width og height

HTML beskriver formen — CSS styrer størrelsen

<img
  src="/images/event-900.webp"
  alt="Koncert på Godsbanen"
  width="900"
  height="500"
/>
Før download900 / 500 = 9 / 5. Browseren kan derfor reservere den rigtige form.
Hvilke tal skriver jeg?Er selve filen 900 × 500? Skriv width="900" height="500".
CSS gør det responsivt 
img {
  max-width: 100%;
  height: auto;
}

CSS bestemmer visningen: Samme fil på 900 × 500 må gerne vises som 450 × 250 eller 100% × auto.

Width og height er ikke en lås på den visuelle størrelse. De fortæller browseren filens proportioner, så pladsen kan reserveres allerede før download og layout-hop reduceres. Brug helst den valgte billedfils faktiske pixelmål. En fil på 900 × 500 får altså width 900 og height 500. Den viste størrelse behøver ikke matche tallene: CSS kan gøre billedet smallere med max-width 100% og height auto. loading gælder native for <img> og <iframe> — ikke CSS, fonte, scripts eller alle andre assets.

Lazy loading er ikke en generel optimeringsknap. Brug det på billeder under folden, fordi de ikke behøver konkurrere om båndbredde under første load. Brug det ikke på hero- eller andre sandsynlige LCP-billeder; de skal opdages tidligt og kan eventuelt få fetchpriority high. Loading-attributten gælder billeder og iframes. JavaScript, fonte og video har andre mekanismer. * kan erstattes med de felter, UI’et bruger

→

Mindre response og en tydelig kontrakt til UI’et.

Feltudvælgelse er en forbedring: Ikke en forudsætning for at forstå relationen.

Genbrug modellen fra i går. Venstre URL er et godt lærings- og kontroltrin: den viser, at nested user-data kommer med. Højre URL er næste skridt, når komponenten er kendt. REST-kaldet til netop dette kort

Greb 4 · JavaScript

Lazy-load PostDetailPage — hvis første bundle er problemet

import { lazy, Suspense } from "react";

const PostDetailPage = lazy(() =>
  import("./pages/PostDetailPage")
);

<Route
  path="/posts/:id"
  element={
    <Suspense fallback={<p>Indlæser post…</p>}>
      <PostDetailPage />
    </Suspense>
  }
/>

lazy()venter med at hente sidens JavaScript, til routen skal vises

Suspenseviser en fallback, mens komponentens kode bliver hentet

Tradeoffmindre første bundle — men et ekstra load, når detaljesiden åbnes første gang

Brug det kun, hvis første JS-load er et dokumenteret problem.
Knyt eksemplet til den eksisterende Post App: App.jsx forbinder allerede /posts/:id med PostDetailPage. En almindelig statisk import lægger normalt page-koden i den JavaScript, der er klar ved første load. lazy() bruger en dynamisk import og venter med at hente modulet, til PostDetailPage skal renderes. Suspense viser fallbacken imens. Modulet skal have en default export, hvilket den eksisterende PostDetailPage allerede har. Gevinsten er ikke mindre samlet kode, hvis brugeren besøger alle routes; koden flyttes til det tidspunkt, hvor den skal bruges. Vis derfor dette som et valgfrit, senere greb. De fleste studerende får mere ud af at optimere billeder og requests først.
