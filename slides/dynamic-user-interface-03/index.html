03 Sessionen og tokens

appen dig

HTTP har ingen hukommelse — hver request er en fremmed.

Session
At du er logget ind. Den starter ved login, slutter ved log ud — og består af to tokens.
Token
Et digitalt bevis: en lang tekst, du får ved login, og som browseren viser frem i stedet for din adgangskode. Nøglekortet 🪪 er et token.

Sessionen · i browseren · opgave 2

Her ligger sessionen

Application → Cookies i Chrome · Storage i Safari og Firefox. Cookien med -auth-token er sessionen.

Tokens · hvad står der i cookien?

Nøglekortet udløber — og bliver fornyet

Access token

Nøglekortet

≈ 1 time og så udløber det

Det token, der beviser, hvem du er. Det sendes med og tjekkes, hver gang du beder om noget beskyttet.

{ "sub": "7f3c…", "email": "dig@eaaa.dk" }
↻
Refresh token

Fornyelsen

Lang levetid men kan kun forny

Det token, der henter et nyt access token, når det gamle er udløbet. Så slipper du for at logge ind igen.

JWT · JSON Web Token
Formatet for access token'et: JSON med en signatur. Alle kan læse det — ingen kan ændre det uden at signaturen går i stykker.
Hvorfor to tokens?
Et stjålet nøglekort virker højst en time. Refresh token'et gør, at du ikke mærker, når det udløber — og det spærres, når du logger ud.

Koden kører
på serveren

— derfor kan siden se, hvem du er, og formularen kan logge dig ind.

Server Component · standard
En komponent, der kører på serveren, når siden hentes. Den kan være async og læse cookies, før HTML'en sendes.
Server Action · "use server"
En funktion med "use server", som en formular kalder, når den sendes. Den kører på serveren og kan sætte cookies.

Next.js · Server Component

Server Component er standard

app/profile/page.js 
import { getCurrentUser } from "@/lib/auth";

export default async function ProfilePage() {
  const user = await getCurrentUser();

  return <p>Email: {user.email}</p>;
}

Intet "use client"Så er den en Server Component. Du skriver ikke noget for det.

async og awaitKomponenten må vente på data, før den returnerer JSX.

getCurrentUser()Læser cookien i requesten. Det kan kun serveren.

returnServeren bygger HTML'en og sender den færdig til browseren.

Hvorfor? Siden ved, hvem du er, før den bliver sendt. Ingen useState, ingen useEffect og ingen loading.

Next.js · Server Action

Server Action ændrer noget

app/signup/page.js · over komponenten 
async function signUp(formData) {
  "use server";

  const email = formData.get("email");
  const password = formData.get("password");

  const supabase = await createClient();
  await supabase.auth.signUp({ email, password });
  redirect("/");
}

<form action={signUp}>…</form>

"use server"Gør funktionen til en Server Action. Den kører på serveren — aldrig i browseren.

action={signUp}Formularen sendes som en POST, og Next.js kører signUp.

formData.get("email")Henter feltet med name="email".

redirect("/")Sender brugeren videre. I opgave 4 til /profile.

Hvorfor? Koden kører på serveren, så den kan logge dig ind og sætte cookien — uden onSubmit og fetch.

Login-flowet · lib/supabase/server.js

Supabase-klienten og cookies

lib/supabase/server.js · forkortet 
export async function createClient() {
  const cookieStore = await cookies();
  return createServerClient(URL, PUBLISHABLE_KEY, {
    cookies: {
      getAll: () => cookieStore.getAll(),
      setAll(cookiesToSet) {
        try {
          cookiesToSet.forEach(({ name, value, options }) =>
            cookieStore.set(name, value, options));
        } catch {
          // Server Components can't write cookies
        }
      }
    }
  });
}

createClient()Laver Supabase-klienten — objektet bag supabase.auth.…, ikke browseren. En ny pr. request, så brugere ikke deler session.

getAll()Læser cookies fra requesten. Sådan ved serveren, hvem der spørger.

setAll()Skriver cookies. Virker i en Server Action — sådan bliver du logget ind. Ikke i en Server Component. Det løser proxy.js.

Og browser-klienten?Den findes også, men i dag taler kun serveren med Supabase.

Beskyttede sider · koden

Hvem er logget ind? Spørg ét sted

lib/auth.js 
export async function getCurrentUser() {
  const supabase = await createClient();
  const { data } = await supabase.auth.getClaims();

  return data?.claims ?? null;
}
app/profile/page.js 
export default async function ProfilePage() {
  const user = await getCurrentUser();

  if (!user) {
    redirect("/login");
  }

  return <p>{user.email}</p>;
}
getClaims()
Tjekker, at nøglekortet er ægte, og giver dig indholdet: email og id'et i sub.
Én regel
Brug getClaims(), når du beskytter noget på serveren. Supabase advarer mod getSession(), som ikke tjekker kortet.
