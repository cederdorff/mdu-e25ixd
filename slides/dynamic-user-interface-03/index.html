Server · Auth

Supabase

har udstedt nøglekortet
  1. Browseren sender cookien med automatisk — du skriver ingen kode til det.
  2. page.js kører på serveren og læser cookien fra requesten.

Hvor bor sessionen? · hvad står der på nøglekortet?

Nøglekortet udløber — og bliver fornyet

Access token

Nøglekortet

≈ 1 time og så udløber det

Viser, hvem du er. Det tjekkes, hver gang du beder om noget beskyttet.

Refresh token

Fornyelsen

Lang levetid men kan kun ét

Bruges til at hente et nyt access token, når det gamle er udløbet. Så slipper du for at logge ind igen.

Formatet for access token'et: JSON med en signatur. Alle kan læse det — ingen kan ændre det uden at signaturen går i stykker.

Login-flowet · trin 1–4 i koden

Server Action'en er én funktion

app/login/page.js · over komponenten 
async function signIn(formData) {
  "use server";

  const email = formData.get("email");
  const password = formData.get("password");

  const supabase = await createClient();
  const { error } = await supabase.auth
    .signInWithPassword({ email, password });

  if (error) {
    redirect("/login?error=true");
  }

  redirect("/");
}

"use server"Øverst i funktionen gør den til en Server Action. Den kører på serveren — også når formularen kalder den.

formData.get("email")Henter feltet med name="email" fra formularen.

?error=trueGik det galt, sendes brugeren tilbage, og login-siden viser en fejlbesked.

redirect("/")Gik det godt, ligger cookien klar, og brugeren sendes videre.

Login-flowet · lib/supabase/server.js

Klienten læser sessionen fra cookies

lib/supabase/server.js · forkortet 
export async function createClient() {
  const cookieStore = await cookies();

  return createServerClient(URL, PUBLISHABLE_KEY, {
    cookies: {
      getAll() {
        return cookieStore.getAll();
      },
      setAll(cookiesToSet) {
        // Server Components can't write cookies
      }
    }
  });
}

createClient()En ny klient pr. request. Delt mellem requests kunne én bruger få en andens session.

getAll()Læser cookies fra requesten. Sådan ved serveren, hvem der spørger.

setAll()Skriver nye cookies — men det må en server component ikke. Det løser proxy.js.

Og browser-klienten?Den findes også, men i dag taler kun serveren med Supabase.

Beskyttede sider · koden

Hvem er logget ind? Spørg ét sted

lib/auth.js 
export async function getCurrentUser() {
  const supabase = await createClient();
  const { data } = await supabase.auth.getClaims();

  return data?.claims ?? null;
}
app/profile/page.js 
export default async function ProfilePage() {
  const user = await getCurrentUser();

  if (!user) {
    redirect("/login");
  }

  return <p>{user.email}</p>;
}
getClaims()
Tjekker, at nøglekortet er ægte, og giver dig indholdet: email og id'et i sub.
Én regel
Brug getClaims(), når du beskytter noget på serveren. Supabase advarer mod getSession(), som ikke tjekker kortet.

Outputtet efter opgave 4

○  (Static)   prerendered as static content

○ StaticBygges én gang og er den samme for alle — som forsiden.

ƒ DynamicBygges ved hver request, fordi svaret afhænger af, hvem der spørger.
