01 AI i udviklingsarbejdet

Chat eller agent?

Forskellen er handling og adgang til kontekst

En chat svarer

  • forklarer et begreb
  • foreslår kode
  • ser kun det, du deler
→

En agent arbejder

  • undersøger filer
  • kører kommandoer
  • ændrer kode og tester

Mere handlekraft kræver mere afgrænsning, review og test.

En agent er ikke automatisk mere korrekt. Den kan bare gennemføre flere led i opgaven. Vis gerne forskellen mellem et løst spørgsmål og en konkret opgave i et åbent repo. [Sources] - https://learn.chatgpt.com/docs/codex/ide [/Sources]

Sikker arbejdsform

Agenten må gerne hjælpe — aldrig overtage ansvaret

  • 01Del kun relevante filer, fejl og logs — aldrig private nøgler, tokens eller hele .env.
  • 02Afgræns ændringen, og bed om forklaring før store eller uklare indgreb.
  • 03Læs diffet. Behold kun ændringer, du forstår og kan forsvare.
  • 04Kør appen, lint og relevante tests. Et overbevisende svar er ikke et testresultat.

En vigtig grænse

VITE_ organiserer værdier — det skjuler dem ikke

Vite erstatter værdierne under build. Derfor kan de læses i den færdige frontend.

Frontend: Supabase publishable key kan bruges sammen med korrekt RLS. Aldrig: secret- eller service-role keys i browseren.

.env betyder ikke hemmeligt. Det betyder konfiguration uden hardcoding. VITE_-værdier ender i klientens bundle. Skeln mellem Supabase publishable key og en serverhemmelig nøgle. [Sources] - https://vite.dev/guide/env-and-mode - https://supabase.com/docs/guides/getting-started/api-keys [/Sources]

05 Supabase

REST er grænsefladen — SDK’et er et værktøj ovenpå

De kan nå de samme data, men de giver os forskellige måder at arbejde på.

Formålet er begrebsforståelse, ikke at migrere starterprojektet i dag. [Sources] - https://supabase.com/docs/guides/api - https://supabase.com/docs/reference/javascript/introduction [/Sources]
Supabase Data REST API

Databasen bliver til HTTP-endpoints

const response = await fetch(
  `${SUPABASE_URL}/rest/v1/posts`,
  {
    headers: {
      apikey: PUBLISHABLE_KEY,
      "Content-Type": "application/json"
    }
  }
);

const posts = await response.json();

URL

Projekt + /rest/v1/ + tabel.

HTTP

Metode, headers, query-parametre og body.

Svar

Statuskode, headers og JSON-data.

Din kode

Håndterer loading, fejl og tomme resultater.

Supabase auto-genererer Data REST API fra database-schemaet via PostgREST. Sammenlign med den konkrete fetch i PostsPage.jsx. [Sources] - https://supabase.com/docs/guides/api - https://github.com/cederdorff/react-router-supabase/blob/main/src/pages/PostsPage.jsx [/Sources]
REST og JavaScript SDK

Samme intention — forskellig mængde håndarbejde

Direkte REST med fetch

const response = await fetch(URL, {
  headers: { apikey: key }
});

if (!response.ok) {
  throw new Error("Kunne ikke hente posts");
}

const data = await response.json();

Supabase JavaScript SDK

const { data, error } = await supabase
  .from("posts")
  .select("*");

if (error) {
  throw error;
}

SDK’et giver os et mere specialiseret sprog til API’et.

Forklar at supabase-js stadig kommunikerer med Supabase-tjenesterne. Query builderen samler URL, headers og parsing i et bibliotek med Supabase-begreber. [Sources] - https://supabase.com/docs/reference/javascript/initializing - https://supabase.com/docs/reference/javascript/select [/Sources]
Hvad får vi med SDK’et?

Én klient samler flere Supabase-produkter

Database

Læs, opret, opdatér, slet, filtrér og hent relationer med en query builder.

Auth

Login, sessioner, brugerdata og tokens i samme klient.

Realtime

Lyt til ændringer og byg interfaces, der opdaterer løbende.

Storage + Functions

Arbejd med filer og kald server-side Edge Functions.

Vi vender tilbage til SDK’et, når auth, relationer og mere avanceret dataarbejde gør abstraktionen værdifuld. [Sources] - https://supabase.com/docs/reference/javascript/introduction [/Sources]
Dagens valg

Vi beholder REST, så netværkslaget forbliver synligt

I dag skal vi kunne se URL, headers, status og JSON.

Senere bruger vi SDK’et, når vi skal bygge mere end simple requests.

Valget handler om læringsmål og kompleksitet — ikke om at REST er “forkert”.

Gør dette eksplicit, så de studerende ikke migrerer starteren som en del af dagens opgave. SDK-introen er en forsmag på senere undervisning. [Sources] - User-provided teaching direction, 17 August 2026 - https://supabase.com/docs/guides/api [/Sources]

Når alt virker vigtigt

Prioritér efter konsekvens — ikke efter hvor let det ser ud

Appen kan ikke bruges

Build, deployment, routing, data eller blokerende runtime-fejl.

Brugere bliver udelukket

Tastatur, labels, fokus, kontrast eller utilgængelige handlinger.

Løsningen er misvisende

Forkert identitet, metadata, indhold eller uforståelige fejl-states.

Koden kan forbedres

Oprydning, navngivning og struktur uden akut bruger- eller driftskonsekvens.

Prioriteringen er en tommelfingerregel. Bed de studerende skrive én sætning: “Vi vælger X først, fordi Y”. [Sources] - User-provided lesson goals and starter-repository audit scope, 17 August 2026 [/Sources]

Find

Vælg et konkret problem i deployment, routing, data, metadata eller accessibility.

Begrund

Forklar for dig selv, hvem problemet påvirker, og hvorfor det er vigtigt.

Forbedr

Lav den mindste relevante ændring. Brug gerne en AI-agent med klare rammer.
