Hvad er en teknisk audit?

Vi undersøger systematisk, før vi beslutter, hvad der skal ændres

Audit

En afgrænset undersøgelse af en eksisterende løsning. Fund dokumenteres og vurderes efter konsekvens.

Evidens er noget, andre kan efterprøve: fx kodehenvisning, skærmbillede, konsol/Network eller keyboard-flow.

Afgræns→Baseline→Undersøg→Prioritér→Verificér

Hvorfor gør vi det?

  • Vi skelner problemer fra personlige præferencer.
  • Vi bevarer et udgangspunkt til før/efter.
  • Vi vælger forbedringer med størst relevant effekt.

I Case 1: Auditobjektet er Mellemrum. Tilmeldingsflowet og den deployede løsning skal altid indgå.

Hold definitionen kort og brug den som ramme for resten af dagen. Audit betyder ikke, at alt skal vurderes eller laves om; undersøgelsen skal være afgrænset og føre til begrundede valg. Målet er ikke at finde flest fejl, men at træffe bedre tekniske beslutninger om Mellemrum. Evidens er dokumentation, som en anden kan efterprøve og bruge til at forstå fundet. [Sources] - Teknisk audit af en React-løsning · lokalt kursusmateriale · undervisning/product-optimization/teknisk-audit-skabelon.md [/Sources]
Audit ≠ personlig kodepræference

Et fund skal kunne forklares med mere end “jeg ville…”

Præference
“Jeg ville flytte filen.”

Ingen tydelig evidens eller konsekvens.

Auditfund
“Datoformatet er gentaget fire steder.”

Kodehenvisninger viser gentagelsen; samme ændring skal vedligeholdes flere steder.

Præference
“Jeg ville bruge CSS Modules.”

En mulig tilgang — men endnu ikke et dokumenteret problem.

Auditfund
“Den globale .button-regel rammer både kort og formular.”

DevTools viser samme selector; en ændring ét sted giver en utilsigtet ændring et andet.

Bed holdet formulere forskellen i begge eksempler. CSS Modules kan være en god løsning, men auditfundet er den observerede kobling mellem selectors og konsekvensen — ikke præferencen for et bestemt værktøj. Et auditfund forbinder observation, evidens og konsekvens; løsningen kan stadig diskuteres. [Sources] - Teknisk audit af en React-løsning · lokalt kursusmateriale [/Sources]

Arbejd nu i Mellemrum · leverance

Registrér tre fund eller hypoteser — uden at rette koden

Obligatorisk scope

  • Gennemfør tilmeldingsflowet lokalt og online
  • Undersøg den deployede version og en direkte route
  • Vælg mindst ét ekstra flow, fx eventdetaljen eller den interne side

  • mindst to gennemførte flows
  • tre rækker i audit-skabelonen

Side effect og Effect

Render beregner UI — useEffect kører efter render

01 · State 
const [posts, setPosts] =
  useState([]);
React husker posts mellem renders.
02 · Effect med side effect 
useEffect(() => {
  async function getPosts() {
    const response = await fetch(URL, { headers });
    setPosts(await response.json());
  }
  getPosts();
}, []);
fetch kontakter et system uden for React.
03 · Render 
return posts.map(post =>
  <PostCard
    key={post.id}
    post={post}
  />
);
JSX beregnes fra den aktuelle state.

Side effect er handlingen uden for render. Effect er Reacts navn for synkroniseringen, som deklareres med useEffect.

“Side effect” er det generelle begreb for arbejde, der påvirker eller bruger noget uden for den rene renderberegning. React-dokumentationen kalder en synkronisering, som skyldes rendering og deklareres med useEffect, en Effect. Ikke alle side effects skal i useEffect: handlinger, der skyldes et konkret klik eller submit, hører normalt i event handleren. En beregning baseret på eksisterende props/state behøver normalt slet ikke et Effect. Kodeudsnittet er forkortet. Adskil forskellige slags arbejde, så de kan ændres hver for sig

Derived state

Kan værdien beregnes, skal den normalt ikke gemmes igen

Undgå at gemme antal separat 
const [posts, setPosts] = useState([]);
const [postCount, setPostCount] = useState(0);

setPosts(data);
setPostCount(data.length);
Beregn antal ud fra posts 
const [posts, setPosts] = useState([]);
const postCount = posts.length;
const hasPosts = postCount > 0;

return <p>{postCount} posts</p>;

Derived state: postCount og hasPosts afledes af posts. Når posts ændres, beregnes de automatisk igen under render.

HomePage bruger allerede posts.length direkte i sine UI-betingelser. Antal er et konkret eksempel på derived state: det er en værdi, der kan beregnes ud fra eksisterende state. Hvis både posts og postCount gemmes, kan en kodevej glemme setPostCount, og værdierne kommer ud af sync. Gem den minimale, komplette state og beregn resten under render. // services/postService.js
const URL = import.meta.env.VITE_SUPABASE_URL;
const headers = { apikey: API_KEY, ... };

async function request(path = "", options = {}) {
  const response = await fetch(`${URL}${path}`, {
    ...options,
    headers
  });

  if (!response.ok) throw new Error(response.status);
