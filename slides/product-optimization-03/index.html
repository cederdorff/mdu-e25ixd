Hvad er fejlhåndtering?

Data kan være forkerte, uden at JavaScript stopper

01 · Problemet er usynligt 
const post = {};

console.log(post.caption);

Output: undefined — programmet fortsætter.

02 · Vi gør problemet eksplicit 
if (!post.caption) {
  throw new Error(
    "Post caption is required"
  );
}

Nu har koden defineret, at en manglende caption er en fejl.

Fejlhåndtering er måden, programmet reagerer på, når noget går galt eller ikke er som forventet.

Begynd helt simpelt: undefined er en værdi, ikke automatisk en kastet fejl. Vi beslutter selv, at caption er påkrævet. [Sources] - MDN: Error · https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Error - MDN: throw · https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Statements/throw [/Sources]

Pointe: Error beskriver, hvad der gik galt.

Et Error-objekt beskriver fejlen, men ændrer ikke programflowet, før det bliver kastet. [Sources] - MDN: Error · https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Error [/Sources]
throw

throw stopper det normale programflow

const post = {};

if (!post.caption) {
  throw new Error(
    "Post caption is required"
  );
}

console.log("Done");
Caption mangler↓throw↓Error sendes videre↓“Done” køres ikke

throw stopper det normale programflow og sender fejlen videre.

[Sources] - MDN: throw statement · https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Statements/throw [/Sources]
Anatomien i try / catch

try og catch har hver sin opgave

01 · try 
try {
  // kode som kan fejle
}

Koden køres normalt. Hvis noget thrower, stopper resten af try-blokken.

02 · catch 
catch (error) {
  // håndtér fejlen
}

catch kører kun ved en kastet fejl. Variablen error modtager fejlen.

Ingen fejltry → spring catch over → fortsæt

Fejltry → throw → catch → fortsæt

Gå langsomt gennem syntaksen. Try betyder ikke, at JavaScript prøver igen; blokken markerer den kode, hvis kastede fejl vi vil kunne fange. Catch kører ikke på happy path. Error-parameteren er det Error-objekt, som blev kastet. Catch løser heller ikke automatisk problemet — vi vælger reaktionen. [Sources] - MDN: try...catch · https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Statements/try...catch [/Sources]
try / catch

Fejlen går fra try til catch

const post = {};

try {
  if (!post.caption) {
    throw new Error(
      "Post caption is required"
    );
  }
  console.log(post.caption);
} catch (error) {
  console.error(error.message);
}
console.log("Done");
try kører↓throw stopper try↓catch modtager error↓“Done” bliver kørt

catch modtager fejlen, så vi kan vælge, hvordan koden skal reagere.

Sammenlign med forrige slide: Her ser vi fejlvejen i et konkret eksempel. Når throw køres, springer JavaScript direkte til catch, så console.log(post.caption) bliver ikke kørt. Catch betyder ikke, at problemet er løst; vi vælger, hvordan koden reagerer, og om programmet skal fortsætte. [Sources] - MDN: try...catch · https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Statements/try...catch [/Sources]

Funktionen forventer at finde en post

const posts = [

function getPost(id) {

Saml loading, error og data

async function getPosts() {
  try {
    setLoading(true);
    setError("");
    const response = await fetch(URL, { headers });
    if (!response.ok) throw new Error(`HTTP ${response.status}`);
    const data = await response.json();
    setPosts(data);
  } catch (caughtError) {
    console.error(caughtError);
    setError("Vi kunne ikke hente opslag");
  } finally {
    setLoading(false);
  }
}

Samme funktion håndterer loading, error og data.
