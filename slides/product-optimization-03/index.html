Hvad er fejlhåndtering?

Data kan være forkerte, uden at JavaScript stopper

01 · Problemet er usynligt 
const post = {};

console.log(post.caption);

Output: undefined — programmet fortsætter.

02 · Vi gør problemet eksplicit 
if (!post.caption) {
  throw new Error(
    "Post caption is required"
  );
}

Nu har koden defineret, at en manglende caption er en fejl.

Fejlhåndtering er måden, programmet reagerer på, når noget går galt eller ikke er som forventet.

Begynd helt simpelt: undefined er en værdi, ikke automatisk en kastet fejl. Vi beslutter selv, at caption er påkrævet. [Sources] - MDN: Error · https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Error - MDN: throw · https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Statements/throw [/Sources]
Hvorfor har vi brug for fejlhåndtering?

Flere ting kan bryde den forventede vej

Data

Caption mangler, eller formatet er forkert.

Operation

Et opslag bliver ikke oprettet eller slettet.

HTTP

Supabase svarer med 400, 404 eller 500.

Netværk

Browseren kan ikke nå serveren.

Vi kan ikke forhindre alle fejl. Men vi kan kontrollere, hvordan programmet reagerer.

De næste slides zoomer ind på Error, throw og try/catch. [Sources] - Post App · lokalt semester 2-projekt - MDN: Control flow and error handling · https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Control_flow_and_error_handling [/Sources]
Error

Et Error-objekt beskriver problemet

const error = new Error(
  "Post caption is required"
);

console.log(error.message);
error.message Post caption is required

Fejlen har nu en besked, som udvikleren kan undersøge.

Et Error-objekt beskriver fejlen, men ændrer ikke programflowet, før det bliver kastet. [Sources] - MDN: Error · https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Error [/Sources]
throw

throw stopper det normale programflow

const post = {};

if (!post.caption) {
  throw new Error(
    "Post caption is required"
  );
}

console.log("Done");
Caption mangler↓throw↓Error sendes videre↓“Done” køres ikke
[Sources] - MDN: throw statement · https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Statements/throw [/Sources]
try / catch

catch giver os kontrollen tilbage

const post = {};

try {
  if (!post.caption) {
    throw new Error(
      "Post caption is required"
    );
  }
  console.log(post.caption);
} catch (error) {
  console.error(error.message);
}
console.log("Done");
try↓Noget fejler↓catch håndterer↓“Done” bliver kørt
Catch betyder ikke, at problemet er løst; det betyder, at vi kan vælge, hvordan koden reagerer, og om programmet skal fortsætte. [Sources] - MDN: try...catch · https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Statements/try...catch [/Sources]

Funktionen forventer at finde en post

const posts = [
  { id: 1, caption: "Aarhus by night" },

function getPost(id) {
  const post = posts.find(post => post.id === id);
  if (!post) {
    throw new Error("Post not found");

Hvad · hvorfor · hvordan

En UI-state beskriver situationen nu

Hvad?

En tydelig visning af systemets aktuelle tilstand.

Hvorfor?

Brugeren forstår, om systemet arbejder eller kræver handling.

Hvordan?

Modellér states, og render det rigtige UI for hver state.

Robust betyder ikke fejlfri. Det betyder forståelig og brugbar — også når noget går galt.

[Sources] - React: Reacting to Input with State · https://react.dev/learn/reacting-to-input-with-state - React: Conditional Rendering · https://react.dev/learn/conditional-rendering [/Sources]
Loading skal altid afsluttes

finally kører efter både succes og fejl

try {
  setLoading(true);
  const response = await fetch(URL, { headers });
  if (!response.ok) throw new Error("HTTP error");
  setPosts(await response.json());
} catch (error) {
  setError("Vi kunne ikke hente opslag");
} finally {
  setLoading(false);
}
Success↘finally↗Error

Loading bliver afsluttet uanset udfaldet.

Hvis setLoading(false) kun står efter fetch, kan en fejl efterlade UI’et i loading. [Sources] - Post App · src/pages/HomePage.jsx · lokalt semester 2-projekt - MDN: try...catch · https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Statements/try...catch [/Sources]

Det komplette React-pattern

Requestets udfald vælger næste UI-state

async function getPosts() {
  setStatus("loading");
  try {
    const response = await fetch(URL, { headers });
    if (!response.ok) throw new Error(`HTTP ${response.status}`);

    const data = await response.json();
    setPosts(data);
    setStatus(data.length === 0 ? "empty" : "success");
  } catch (error) {
    console.error("Could not load posts", error);
    setStatus("error");
  }
}

Fejlhåndteringen afgør udfaldet. React-state gør udfaldet tilgængeligt for UI’et.

Nu kobles de to faglige dele eksplicit sammen. Status sættes til loading før requestet og får derefter præcis ét af tre udfald.
