01 Moduler, import og export

Vi deler koden op i filer, før vi deler den op i komponenter

Alt i dag bygger videre på den samme mekanik: export ét sted, import et andet.

Forstå · Moduler

Hvorfor dele koden op i filer?

Genbrug

En funktion skrevet ét sted kan bruges mange steder i projektet.

Overblik

Hver fil får ét ansvar, så koden er lettere at finde og forstå.

Navnerum

export og import styrer, hvad der er synligt uden for filen.

export gør noget tilgængeligt uden for filen. import henter det ind i en anden fil. En React-komponent er i bund og grund bare en exporteret function.

JavaScript · i web-app-optimization

Opret dit første modul i src/playground/

// src/playground/greetings.js
export function greet(name = "der") {
  return `Hej, ${name}!`;
}
// src/main.jsx (midlertidigt, mens du øver)
import { greet } from "./playground/greetings.js";

console.log(greet("Mette"));

Åbn browserens devtools-console for at se resultatet, mens appen kører lokalt.

React · samme projekt

Komponenter er også bare import og export

// src/components/Greeting.jsx
export function Greeting({ name = "der" }) {
  return <p>Hej, {name}!</p>;
}
// src/App.jsx
import { Greeting } from "./components/Greeting.jsx";

Samme mekanik som i src/playground/: én fil exporterer, én anden importerer. Kun navnet ændrer sig — function bliver til component.

02 Variabler og datatyper

const, let, var — og hvad de indeholder

Det, du gemmer i en variabel, styrer, hvordan resten af koden opfører sig.

Forstå · Variabler og datatyper

Tre måder at deklarere en variabel på

const

Kan ikke gentildeles. Brug den som standard for alt, der ikke skal ændre sig.

let

Kan gentildeles. Brug den kun, når værdien reelt skal ændre sig.

var (undgås)

Function scope i stedet for block scope, og kan give overraskende bugs. Brug ikke var i ny kode.

Datatyper: string, number, boolean, object, array, null/undefined. === sammenligner værdi og type. == kan konvertere typer og give overraskelser — brug altid ===.

JavaScript · i web-app-optimization

Deklarér, beregn og sammenlign i src/playground/variables.js

export const price = 99;
let quantity = 2;
quantity = 3;

export const total = price * quantity;

console.log(typeof price, typeof "kop", typeof true);
console.log(1 === "1", 1 === 1);
React · samme projekt

State er React’s svar på “en værdi, der må ændre sig”

function ProductCard({ price, quantity }) {
  const total = price * quantity; // const – ændrer sig ikke i denne render
  const [inStock, setInStock] = useState(true); // værdien må ændre sig via setInStock

  return (
    <p>
      {total} kr. – {inStock ? "På lager" : "Udsolgt"}
    </p>
  );
}

Du opdaterer aldrig inStock direkte, som du ville med let — du kalder altid setInStock(...).

03 Functions og arrow functions

En komponent er bare en funktion, der returnerer markup

Parametre er input. Return-værdien er output.

Forstå · Functions

Parametre ind — return-værdi ud

Function declaration

function navn() {} — den klassiske skrivemåde.

Arrow function

const navn = () => {} — kortere syntaks, bruges ofte i React.

Parametre og return

Parametre er funktionens input. return er dens output — uden return får du undefined.

Ekstra: default parameters giver en parameter en standardværdi. Callback functions er funktioner, der sendes som argument til en anden funktion. En closure er en funktion, der “husker” variabler fra det sted, den blev skabt.

JavaScript · i web-app-optimization

Skriv functions i src/playground/functions.js

export function add(a, b) {
  return a + b;
}

export const multiply = (a, b) => a * b;

export function formatPrice(price, currency = "kr.") {
  return `${price} ${currency}`;
}
React · samme projekt

Parametre bliver til props — return bliver til JSX

function PriceTag({ price, currency = "kr." }) {
  return (
    <span>
      {price} {currency}
    </span>
  );
}

function BuyButton({ onBuy }) {
  return <button onClick={() => onBuy()}>Køb</button>;
}

onBuy er en callback function — helt som når du sender en funktion som argument i almindelig JavaScript.

04 Objekter og arrays

State i React må aldrig ændres direkte

Property access, destructuring, rest og spread er værktøjerne, der gør det muligt.

Forstå · Objekter og arrays

Fra property access til immutable opdatering

Property access

product.price eller product["price"] — og shorthand properties, når variabelnavn og property-navn er ens.

Destructuring

Pak værdier ud af et objekt eller array i én linje — i stedet for at læse dem enkeltvis.

Rest og spread

...rest samler resten op. { ...product } kopierer ind i et nyt objekt eller array.

Immutability: Opdatér altid en kopi — aldrig originalen direkte. Det er sådan, React opdager, at noget har ændret sig.

JavaScript · i web-app-optimization

Destructuring, rest og spread i src/playground/objects.js

const name = "Kop";
const price = 99;
const product = { name, price }; // shorthand properties

const { name: productName, ...rest } = product;

const updated = { ...product, price: 79 };

const products = [product];
const withNew = [...products, { name: "Fad", price: 149 }];
React · samme projekt

Immutability er reglen bag setState

function updatePrice(products, name, price) {
  return products.map((p) =>
    p.name === name ? { ...p, price } : p
  );
}

setProducts((prev) => updatePrice(prev, "Kop", 79));

React sammenligner den gamle og den nye reference. Ændrer du et objekt direkte, opdager React det ikke.

Opdatér array

Du er klar, når: Du kan vise, at originalen ikke ændres, når du opdaterer kopien.

05 Array-metoder og rendering

JSX er bare JavaScript-udtryk i markup

map, filter og find løser hver deres opgave.

Forstå · Array-metoder

Tre metoder — tre formål

map

Transformerer hvert element 1:1 og returnerer en ny array af samme længde.

filter

Vælger en delmængde af elementer, der opfylder en betingelse.

find

Returnerer ét element — eller undefined, hvis intet matcher.

Ekstra: forEach (ingen returværdi), some/every (boolean-svar), includes (findes værdien?) og reduce (byg én samlet værdi).

JavaScript · i web-app-optimization

map, filter, find i src/playground/arrays.js

const cheap = products.filter((p) => p.price < 100);
const names = products.map((p) => p.name);
const found = products.find((p) => p.name === "Kop");
React · samme projekt

map bygger både data og JSX-elementer

function ProductList({ products }) {
  return (
    <ul>
      {products.map((p) => (
        <li key={p.name}>{p.name}</li>
      ))}
    </ul>
  );
}

key er det eneste, der er nyt — resten er samme map, som du lige har skrevet.

06 Udtryk der styrer visning

De samme udtryk styrer, hvad JSX viser

Template literals, ternary, &&/||, ?. og ??.

Forstå · Udtryk der styrer visning

Fem små byggesten

Template literals

`${navn}` i stedet for "" + navn + "" — nemmere at læse end konkatenering.

Ternary

betingelse ? a : b — vælger mellem to værdier.

Truthy/falsy og &&/||

De fleste værdier er “sande” — kun false, 0, "", null, undefined og NaN er falske.

?. (optional chaining) stopper roligt, hvis noget mangler undervejs. ?? (nullish coalescing) bruger kun en fallback ved null/undefined — ikke ved 0 eller "", som || ville gøre.

JavaScript · i web-app-optimization

Byg udtryk i src/playground/expressions.js

const label = `${product.name} – ${product.price} kr.`;
const oldLabel = product.name + " – " + product.price + " kr.";

const status = product.inStock ? "På lager" : "Udsolgt";
const count = product.stock ?? 0;
const description = product.description?.slice(0, 40);
React · samme projekt

Samme udtryk styrer, hvad der bliver vist

function ProductStatus({ product }) {
  return (
    <p>
      {product.inStock ? "På lager" : "Udsolgt"}
      {product.stock > 0 && <span> ({product.stock} tilbage)</span>}
    </p>
  );
}

&& viser kun højresiden, hvis venstresiden er sand — ellers viser React ingenting.

07 Async: fetch med await

Data kommer ikke med det samme

fetch returnerer en promise. await venter på den.

Forstå · Async

En promise er et løfte om en fremtidig værdi

Promise

fetch(...) returnerer med det samme et løfte — ikke selve dataen.

async

En async function returnerer altid selv en promise.

await

Venter på, at en promise bliver opfyldt, og giver dig værdien direkte.

Ekstra: Før async/await skrev man .then() og .catch(). Det er samme mekanik — bare med kortere syntaks. Callback functions er forfaderen til begge.

JavaScript · i web-app-optimization

Hent data i src/playground/async.js

export async function loadProducts() {
  const res = await fetch("/api/products");
  const data = await res.json();
  return data;
}

loadProducts().then((products) => console.log(products));
React · samme projekt

Data fetching hører hjemme i useEffect

useEffect(() => {
  async function load() {
    const res = await fetch("/api/products");
    const data = await res.json();
    setProducts(data);
  }

  load();
}, []);

load() er den samme async-funktion, du lige har skrevet — den kaldes bare inde fra useEffect.
