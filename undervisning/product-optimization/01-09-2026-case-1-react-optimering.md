# RACE - Product optimization: Case 1 · Datamodellering, relationer og Supabase - 01-09-2026

## Formål

At bygge videre på de studerendes erfaring med simpel CRUD ved at forbedre løsningens datamodel og gøre kommunikationen mellem React og Supabase mere overskuelig og robust.

Efter undervisningen skal du kunne modellere en enkel relation mellem tabeller, hente relaterede data med Supabase og adskille dataadgang fra præsentationslogik.

## Forberedelse

- Medbring den seneste version af din løsning.
- Find de steder, hvor løsningen bruger den CRUD, filtrering eller sortering, I arbejdede med på 2. semester.
- Notér, om løsningen bruger Supabase SDK, direkte REST-kald eller begge dele.

## Agenda

1. Fra flere isolerede tabeller til en sammenhængende datamodel
2. Post App-eksempel: Gem først navn og avatar direkte på hver post
3. Undersøg konsekvenserne af duplikerede og inkonsistente brugerdata
4. Primærnøgler, fremmednøgler og relationen: Én bruger kan have mange posts
5. Opdel data i `users` og `posts`, og hent de relaterede data med Supabase SDK
6. Sammenlign Supabase SDK med den kendte REST/fetch-tilgang
7. Saml forespørgsler og mutationer i et tydeligt data- eller service-lag
8. Håndtér loading, fejl, tomme resultater og brugerfeedback konsistent
9. Overfør princippet til relationen i den eksisterende case-løsning
10. Review: Er datamodellen og koden lettere at forstå og videreudvikle?
